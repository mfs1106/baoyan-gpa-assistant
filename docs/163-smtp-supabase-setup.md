# 163 邮箱 SMTP 配置（保研绩点助手）

本项目的注册验证码、重发验证码和找回密码邮件由 Supabase Auth 自动发送。不要把任何邮箱密码或授权码写入本仓库、GitHub Actions 变量、`.env` 文件或前端代码。

## 一、在专用 163 邮箱中完成（由邮箱持有人操作）

1. 登录 163 邮箱网页版。
2. 打开“设置”，查找“POP3/SMTP/IMAP”或“客户端授权密码”。
3. 开启 SMTP 服务，按页面要求完成手机安全验证。
4. 生成客户端授权密码并妥善保存。

客户端授权密码不是邮箱登录密码。若怀疑泄露，请立即在 163 邮箱设置中撤销并重新生成。

## 二、在 Supabase Dashboard 中完成（由项目管理员操作）

打开本项目的 `Authentication → Emails → SMTP Settings`，启用 Custom SMTP，并填写：

| 配置项 | 值 |
| --- | --- |
| SMTP Host | `smtp.163.com` |
| SMTP Port | `465` |
| SMTP User | 专用 163 邮箱的完整地址 |
| SMTP Password | 第一步生成的客户端授权密码 |
| Sender email | 同一个专用 163 邮箱地址 |
| Sender name | `保研绩点助手` |

保存前请确认：授权密码只输入 Supabase 的受保护密码框，绝不粘贴到本项目文件或 GitHub。

## 三、验证码模板和频率

1. 在 `Authentication → Emails → Confirm signup` 的模板中使用 `{{ .Token }}`，使注册邮件展示验证码，而不是仅展示确认链接。
2. 在 `Authentication → Rate Limits` 中，本项目将 Auth 邮件总发送速率设置为每小时 `30` 封。
3. 本网站已对“重新发送验证码”增加 60 秒倒计时；Supabase 仍负责服务端限流。

每小时限制不是严格的“每天 50 封”总量预算。若未来必须硬性限制每日总数，需要额外实现服务端计数和队列；当前小规模使用时，请持续观察 163 邮箱的实际送达情况。

## 四、上线前测试

1. 用一个非项目成员的外部邮箱注册，确认能收到 6 位验证码。
2. 输入验证码，确认能够自动登录。
3. 等待 60 秒后测试一次重发。
4. 测试一次“忘记密码”（若页面后续启用该入口）。
5. 在 Supabase 的 Auth Logs 中确认没有 SMTP 认证或发送错误。

如出现 SMTP 认证失败，先确认 SMTP 服务已开启、用户名为完整邮箱地址、密码为客户端授权密码，再重新生成授权密码进行一次测试。
